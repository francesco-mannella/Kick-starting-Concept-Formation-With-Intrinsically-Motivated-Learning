# 12. The actuator

Complete description of the actuator of the gripper-grasping task as built on branch `dof8` (8 outputs), the measured properties of its input layer, and the embedding variant tested on branch `embed_actuator`. Files: `src/SMAgent.py`, `src/GripAgent.py`, `src/Actuator.py`, `src/grip_map_v2.py`, `src/GripMapping.py`, `src/embedding_map.py`, `src/embedding_diagnostics.py`, `tools/box2dsim/box2dsim/envs/Box2DSim_env.py`.

## 1. Overview and data flow

One simulator step is: observation -> `SMAgent.step` -> `GripAgent.step` -> `Actuator.step` -> action -> `Box2DSim_env.set_action`.

1. `SMAgent.step(state)` builds the actuator state `[touch (40), JOINT_POSITIONS (8), EYE_POS reversed (2)]`, 50 numbers.
2. `Actuator.hidden` encodes the state into the hidden vector (75 units in the champion; 15 in the embedding variant).
3. `Actuator.step` computes `out = hidden @ params` (params: hidden x 8) and applies the output function (`tanh` in the champion; `clip` to [-1, 1] by default).
4. `SMAgent.step` multiplies the output by the signs `[-1, -1, -1, 1, 1, 1, 1, 1]` and adds the bases: `policy_base_arm` (three values, `pi * [0.2, -0.3, -0.4]`) to the arm, `policy_base_wrist` (0.0) to the wrist, `policy_base` (0.8) to each of the four finger commands. The result is the 8-vector action.
5. The environment clips it: arm and wrist targets to +-pi/2, finger commands to [0, pi/2] (close only).

The actuator weights `params` are the policy. The policy map of the main algorithm (report 02) holds one `params` vector per prototype, scaled by `policy_params_amplitude` before it reaches the actuator (`SMAgent.updatePolicy`). The actuator input layer (map, normalisation, embedding) is fixed during agent learning.

## 2. The 8-DoF plant

Action layout: `[arm1, arm2, arm3, wrist, f1_prox, f1_dist, f2_prox, f2_dist]`, in the order of `joint_names` and of `JOINT_POSITIONS`:
`Base_to_Arm1, Arm1_to_Arm2, Arm2_to_Arm3, Arm3_to_Wrist, Wrist_to_Claw11, Claw11_to_Claw12, Wrist_to_Claw21, Claw21_to_Claw22`.

- Finger setpoints from a command `c = clip(cmd, 0, pi/2)`: `Wrist_to_Claw11 = -c`, `Claw11_to_Claw12 = +c`, `Wrist_to_Claw21 = +c`, `Claw21_to_Claw22 = -c` (`finger_signs` in the environment). The joint positions the agent observes therefore have opposite signs for the two fingers when they close together.
- A zero action is the open rest pose, identical to the earlier 5-output environment.
- The wrist is a palm link (`Wrist` body, 1.4 x 0.4, density 5.0) between the tip of `Arm3` and the claws, joint `Arm3_to_Wrist` (revolute, motor 10000). A light palm (density 0.5) made the finger joints unstable and cross-coupled (wrong-sign angles); the settling test in `test_env_8dof.py` guards this.
- Collision filters: arm and wrist category 2 (mask excludes claws and sensors), claws category 4, sensors category 8. The 40 touch sensors are welded to the claw links (4 groups of 10).
- World files are generated by `tools/box2dsim/box2dsim/models/add_wrist.py` (idempotent) for the five worlds.

## 3. Input encoding (`Actuator.py`)

Input blocks: touch (40), joints (8), eye position (2), `input_blocks=(40, 8, 2)`. The hidden layer has `num_hidden` units, three equal blocks of 25 in the champion. Encodings (`grip_encoding`):

- `linear`: `hidden = state @ map` (map: 50 x 75, block-diagonal). Default of `Parameters`.
- `wta_block`: per block the winner unit takes a Gaussian bump over the 5 x 5 grid (`bumps`, width `side / 5`), other units zero.
- `rbf_block` (champion): per block, `act_i = exp(-0.5 * d_i^2 / sigma_b^2)`, `hidden_b = act / sum(act)`. `d_i` is the Euclidean distance between the block input and prototype `i` of the SOM, after normalisation; `sigma_b` is the square root of the median nearest-neighbour squared distance between prototypes (`rbf_sigma`, stored in the norm file). A block becomes a soft one-hot over 25 cells.
- `embedding` (variant, section 8): the hidden vector is a fixed low-dimensional code, no SOM.

Normalisation (`grip_input_norm='block_rms'`): `state = (state - mean) / scale` with per-input `mean` and `scale` from the norm file. Touch scale is one number, the rms over all babbling touch values; joints and eye are centred and scaled by their rms. After the encoding, a per-block gain (`gain_<encoding>`, from the norm file, makes each hidden unit have rms 1 on babbling data) is applied and the touch block is further multiplied by `grip_touch_gain` (3.0 in the champion). Optional `grip_basis_name`: whitened PCA basis of the hidden activity, giving `r x 8` policy weights (not used by the champion; report 09 found no benefit).

## 4. How the input map is built (`grip_map_v2.py`)

- **Babbling** (`collect_babbling`): trials against randomised objects (stretch 1, 1.5 or 2; rotation 0, pi/4 or pi/2; position jitter; worlds 1-3). Actuator outputs `u` in [-1, 1]^8 follow a random walk (step 0.35 every 5 simulator steps, half of the trials start at zero) and are mapped exactly as in `SMAgent.step` (signs, bases), so only commandable postures are visited. Stored per step: touch (40), posture (8), eye (2), and `near` (frames within 10 steps of a touch). Map v4 uses 2000 trials in four files (`babble_1..4.npz`, 200 000 frames).
- **Block statistics** (`block_stats`): `mean` and `scale` as in section 3.
- **SOMs** (`build_maps`, `PrototypeGenerator` in `GripMapping.py`): one 5 x 5 SOM per block, trained with Adam (`lr=0.01`, 100 epochs, batch 50, neighbourhood sigma annealed from `units / 2` to 0.7, loss modulation 2.0 annealed). Touch SOM: contact frames only, resampled so each of the four sensor groups carries equal mass (`balanced_touch`, optionally plus synthetic contact patches). Posture SOM: half near-contact frames, half all frames. Eye SOM: all frames. The 50 x 75 map is block diagonal: rows 0-39 x columns 0-24 (touch), rows 40-47 x 25-49 (posture), rows 48-49 x 50-74 (eye).
- **Files**: `src/data/StoredGripActuatorMap_v4.npy` (50 x 75) and `StoredGripActuatorNorm_v4.npz` (`mean`, `scale`, `gain_linear`, `gain_wta_block`, `gain_rbf_block`, `rbf_sigma`). For v4: `gain_rbf_block` = [18.13, 12.44, 10.65]; all 25 posture units are used in babbling.

## 5. Policy and output

- Policy size: `grip_hidden * grip_output` = 75 x 8 = 600 weights per prototype (champion), 15 x 8 = 120 for the embedding variant.
- Output function `grip_out_fn='tanh'`; the executed policy is the prototype plus Gaussian noise with std `base_policy_noise + (max_policy_noise - base_policy_noise) * local_incompetence`; `noise_share` is the share of executed-policy variance that is noise (88% to 99% in the champion, report 11).
- `policy_params_amplitude`: 0.07 (default since report 11). With the former value 8 the pre-tanh output had a median of about 200 and the output was always +-1; at 0.07 the median is about 1.9 (33% of outputs above 3), at 0.03 about 1.0.
- `touch_gate=True` multiplies the touch-modality match by the contact indicator (`SMController.computeMatchSimple`): a zero touch input gives match 0.

## 6. Measured properties of the input layer

Data: visited states of the five 8-DoF pilot seeds at epoch 150 (36 evaluation episodes x 3 evaluation seeds each; `src/embedding_diagnostics.py collect`) against 20 000 babbling frames. Table in `~/tmp/kss/embed_probe/embedding_diagnostics.csv`.

| Block | Units with winner share above 1%, babbling / visited | Winner entropy (normalised), babbling / visited | Linear readout R^2 of the input from the RBF code, babbling / visited |
|---|---|---|---|
| touch (contact frames) | 21 / 20 | 0.91 / 0.82 | 0.75 / 0.46 |
| posture (8 joints) | 25 / 18 | 0.97 / 0.85 | 0.71 / 0.54 |
| eye | 25 / 22 | 0.99 / 0.90 | 0.89 / 0.81 |

- Posture is an 8-d space cut into 25 cells and the agent visits 18 of them; a linear readout of the 8 joint angles from the 25 RBF activations has R^2 0.54 on visited states.
- Visited posture is not confined to a small region: the per-joint SD on visited states is 0.55 (gripper) to 0.9 (arm) of the babbling SD.
- Visited eye SD is 1.4 to 1.5 times the babbling SD, and visited touch (contact frames) has larger standardised spread than babbling (SD 1.4 to 2.5 against 0.88), so babbling under-covers real contacts. Touch is in contact in 12% to 28% of the visited steps per seed.

## 7. Known limitations

- Each seed settles on one nearly constant posture independent of the object (report 11 and memory notes on constant policy). In seed 0 of the 8-DoF pilot finger 1 is bent at its distal joint and finger 2 straight in 27% of the steps; in the other four seeds both fingers close (steps with one bent and the other straight: at most 1%).
- A posture is observed at 25-cell resolution; the cell index, not the angles, reaches the policy.
- The simulator is symmetric between the fingers (equal commands give mirrored angles) and random babbling shows no touch advantage for either asymmetric arrangement, so the asymmetry in seed 0 comes from learning.

## 8. Embedding variant (branch `embed_actuator`)

Idea: replace the three SOM blocks by a fixed low-dimensional code of the same inputs.

Code (`encoding='embedding'`, `embedded` in `Actuator.py`, fit by `src/embedding_map.py`):
- arm (3), gripper (5) and eye (2): the standardised values themselves (`(x - mean) / scale`); linear PCA of these blocks is a rotation (R^2 1.0 on visited states for 3, 5 and 2 components), kernel PCA brings no gain (arm 0.95, gripper 0.98) and is worse for the eye (0.55), so no further transform is applied;
- touch (40): 5 whitened principal components of contact frames (centred, divided by the component SDs), zero code when no sensor is active; the touch block is multiplied by `grip_touch_gain`;
- the code has 15 numbers, the policy has 15 x 8 = 120 weights (`grip_hidden=15`, `grip_norm_name` = embedding file).
Variant B fits the touch PCA on babbling contact frames (`StoredEmbedding_babble_v1.npz`); variant C pools them with the contact frames visited by the pilot runs (`StoredEmbedding_pooled_v1.npz`, fixed from the A runs only).

Phase 0 numbers for the 5-d touch code: linear PCA R^2 0.59 on babbling and 0.30 on visited contacts (the SOM-RBF code has 0.46 on visited), which motivates variant C.

Test: `test_embedding_actuator.py` (shapes, zero touch code, unit-scale codes, finite output).

Ladder (150 epochs, 5 seeds each, champion options otherwise): A is the current v4 SOM-RBF (the `dof8` pilot runs, epoch 150); B and C at amplitude 0.07, 0.15 and 0.3 (runs end at epoch 149). Variants D and F of the plan (nonlinear or cross-modal layer) were not run because B and C did not reach A.

The two variants differ only in the touch fit (babbling or babbling plus visited contacts), so with five seeds this contrast is not explained and the swap result of B is not a stable finding. - Asymmetric fingers: the share of steps with one distal bent and the other straight is at most 0.04 in every embedding condition (0.058 in A, driven by seed 0), so there is no sign that the embedding changes the fixation or makes it worse; it also does not show a gain, since A's pattern appears in one seed only.
- Saturation census (`~/tmp/kss/signal_analysis/sat_census.py`, steps with a policy, mean over 5 seeds; B and C at amplitude 0.3 at epoch 149, A at amplitude 0.07 at epoch 150):

  At amplitude 0.3 the embedding is not more saturated than the champion, so saturation does not explain its lower success. Decision: the 15-number embedding does not improve on the SOM-RBF actuator in this budget (success lower, touch lower, policy dependence not reproducible). It stays an option (`encoding='embedding'`, default off); the champion is unchanged.

## 9. Wider fovea (branch `fovea`)

The fovea is a 4 x 4 task-unit window (the table is 60 x 60) sampled at 10 x 10 pixels (0.4 units per pixel), centred on a saliency-sampled eye position that changes every 5 simulator steps. New parameter `fovea_range` (default 4, bit-identical to the former behaviour, `test_fovea.py`) sets the window width and height; it is applied in `SMEnv.reset` so that reloaded checkpoints use it too. The pixel count stays 10 x 10 (visual input 300). Vision enters the algorithm only through the visual map that selects goals (the match uses touch and proprioception only and the actuator sees the eye position, not the retina).

Retina content (`src/fovea_diagnostics.py`, 1728 samples per range, cross-validated by episode; `~/tmp/kss/fovea_probe/phase0/`):

|---|---|---|---|---|
| 4 | 21 | 0.13 | 1.00 / 0.95 / 0.78 | 0.46 |

Result: no width passes the acceptance rule of the plan. The eta2 of context, stretch and rotation stay at their permutation 95th percentile at every width, the swap cost stays below 0.07, and the policy-similarity measures (nodes used, participation ratio of the prototypes, prototype spread against noise) are the same as with the 4-unit window. F12 lowers success (-0.13 [-0.24, -0.01]) and touch frequency (0.13, below the 0.15 floor); F16 has the highest success (0.82) but inside the seed spread (SD 0.20) and its constant-policy cost is not different from A. A wider fovea does not make the policies more distinct. The fovea stays at 4. Open, not part of this test: more pixels at the same width, and giving the actuator a foveal summary (a separate decision).
